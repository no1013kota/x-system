## 結論

Xのおすすめ（For You）に載る鍵は「いいねの数」だと思われがちだが、2026年8月13日に公開されたランキング重みでは、いいね0.5に対し報告（通報）は-234、ミュートは-58.8。**否定シグナル1件が、いいね数百件ぶんを打ち消す**設計だ。伸ばす工夫の前に「興味のない人に届いたとき嫌がられない」投稿設計が先だと考えている。

## なぜそうなるのか — 公開されたコードの仕組み

Xの推薦アルゴリズムは、2026年8月13日にGitHubの [xai-org/x-algorithm](https://github.com/xai-org/x-algorithm) で大幅に拡張公開された。[TechCrunchの報道](https://techcrunch.com/2026/08/13/x-open-sources-its-ranking-algorithm-letting-users-see-if-theyve-been-shadowbanned/)によると公開範囲は従来の10〜15倍で、今回初めて**重みの具体値**まで含まれた（[2023年の公開](https://github.com/twitter/the-algorithm)では見えなかった部分だ）。

READMEに書かれた流れは4段階だ。

1. **候補生成** — フォロー中の投稿と、埋め込み検索（Phoenix retrieval）・クラスタ（SimClusters）で探した投稿を集める
2. **事前フィルタ** — 重複・**48時間より古い投稿**・ブロック/ミュート相手・既読を落とす
3. **スコアリング** — Phoenixが「この読者が各行動をとる確率」を予測し、`最終スコア = Σ(重み × 行動の確率)` で合計する
4. **事後フィルタ** — 表示・非表示・警告の可視性判定

重みの実物は [home-mixer/params/param.rs](https://github.com/xai-org/x-algorithm/blob/main/home-mixer/params/param.rs) にある（以下は2026-08-22時点）。

| 行動 | 重み |
|---|---:|
| いいね | 0.5 |
| リポスト | 1.0 |
| 共有 | 2.0 |
| 著者をフォロー | 4.0 |
| 返信 | 5.0 |
| 引用 | 5.0 |
| DMで共有 | 5.0 |
| リンクコピーで共有 | 20.0 |
| **相互フォロー相手からの返信（加算ブースト）** | +15.0 |
| 興味なし | **-43.2** |
| 著者をブロック | **-31.2** |
| 著者をミュート | **-58.8** |
| 報告 | **-234.0** |

この表から読み取れることは3つある。

- **会話は、いいねの10倍重い。** 返信5.0はいいね0.5の10倍。相互フォロー相手からの返信には+15.0が上乗せされる。
- **否定は、桁が違う。** 報告-234はいいね468件ぶんのマイナス。届く範囲を広げるほど、興味のない読者に当たる面も増える。
- **重みが掛かるのは実数ではなく「予測確率」。** 「否定されそうな投稿」は、実際に報告される前から読者ごとのスコアで沈む。

### Grokはどこで使われているのか

「アルゴリズムはGrokになった」と語られがちだが、公開コードでは役割が3つに分かれている。

1. **採点係のPhoenix。** [phoenix/README](https://github.com/xai-org/x-algorithm/blob/main/phoenix/README.md)には、初期公開版のtransformerを「Grok-1のオープンソースリリースから移植した」と明記されている（現在は本番実装を公開）。読者の閲覧履歴と候補投稿から、いいね・返信・滞在時間など**64種類の行動確率を1回で同時予測**し、ここに前述の重みが掛かる。
2. **検品係のGrox。** 投稿された瞬間にテキストと画像・動画を読み、スパム等の分類と後段モデル用の数値表現を作る（メインREADMEの「Content Understanding」）。ハッシュタグの一致ではなく、内容そのものが機械に読まれてから配信が始まる。
3. **非公開の違反予測。** Grokで投稿のルール違反を予測するシステムだけは、スパム業者への対策として今回も公開されていない（前掲TechCrunch）。

つまり「Grok対策」という特別な何かは無い。**内容が全文読まれ、読者ごとに64種類の行動確率で採点される**——表面のタグや定型テクニックが効きにくくなった、と理解する方が実態に近いと考えている。

## 具体例 — 重みから逆算した投稿設計

私はExos AIというX運用ツールを個人で運営していて、生成プロンプトの規約をこの構造に合わせている。設計は次の4つ。

1. **1ポスト1内容・60〜120字目安。** 詰め込むほど「誰向けか分からない投稿」になり、興味のない読者に当たる面が増える。絞った短い投稿は否定シグナルの期待値を下げると考えている。
2. **1ポスト目は単独で意味が通るフックにする。** タイムラインには1ポスト目しか出ない。そこで意味が通らないと返信も引用も生まれない（返信5.0・引用5.0が取れない）。
3. **ハッシュタグは使わない。** 内容は埋め込み（意味のベクトル）で読まれる。タグの羅列は読者には雑音で、「興味なし」を押される面だけが増えると考えている。
4. **ニュース系は当日中に投稿する。** 事前フィルタが48時間より古い投稿を候補から外すため、鮮度を失った時事ネタは土俵に乗らない。

数字の補足: 上の重みは公開コードからの引用で、自分のアカウントでの効果量（何%伸びたか）は未計測。効果を断言する話ではなく、公開された採点基準に投稿設計を合わせているという話だ。

## やらないこと・落とし穴

- **エンゲージメントベイト（「RTした人フォローします」型）。** 返信・リポストを稼げても、興味のない読者に届いた瞬間「興味なし-43.2」「ミュート-58.8」を積む。桁が違う以上、割に合わないと考えている。
- **「リンクを貼ると死ぬ」という定説の鵜呑み。** 公開された重みでリンクを開く行動は+0.2の小さな正の値で、リンクの存在自体への減点は今回読んだ範囲に見当たらなかった。断定はしないが、「貼ったら終わり」という単純な話ではない。
- **今日の重みの暗記。** READMEには本番の値を定期的にコードへ反映すると書かれており、上の値は「2026-08-22時点」のもの。値より「否定が桁違いに重い」「実数でなく予測確率に掛かる」という構造を覚える方が長持ちする。

## まとめ

持ち帰りは1つ。**Xのおすすめは加点計算ではなく、減点が桁違いに大きい採点**だということ。いいねを増やす施策より先に「興味のない人に届いたとき嫌がられないか」を確認する方が、公開された採点基準に合っている。

次にやることも1つ。直近10投稿を見返して「誰向けか1行で言えない投稿」を数えてみてほしい。多いほど否定シグナルをもらう面が広い。[Exos AI](https://exosai.net)の同梱プロンプトも、この採点基準に合わせて書いている。
