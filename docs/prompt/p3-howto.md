# P-3 ノウハウ・ハウツー

| 項目 | 内容 |
|---|---|
| 形 | 目次型メインポスト＋1ステップ1ポストのスレッド |
| 主に狙う反応 | 保存（最強シグナル）・プロフィールクリック |
| プロンプト本文 | `src/lib/prompts/gen-prompts.ts` `PT_P3`（写し: プロンプト設計書 §6.4） |
| 更新日 | 2026-09-01 |

## 参考にした実例・型（リサーチ 2026-09-01）

- **チェックリスト/手順テンプレ型**: 「伸びるツイートの型8選」「月30万稼ぐ方法5ステップ」— 番号付きで整理された情報は「あとで見返す理由」を作り保存が増える。滞在時間も延びる（[addness 伸びるポストの型](https://addness.co.jp/media/twitter-imp/)）。
- **2026年のアルゴリズムでは保存（ブックマーク）がいいねより強いシグナル** — 実用価値の指標として扱われる（検索結果の複数記事で一致）。
- **数字フック**: 「◯◯で失敗した3つのこと」「◯分→◯分」— 冒頭の数字が読む理由と全体量の予告を兼ねる。
- **NG**: 「箇条書き羅列だけで主張がない」「意識する・工夫するで済ませる」は伸びない（同上）。

## 構造分解

| 要素 | 効果 |
|---|---|
| 悩み→変化を数字で（1行目） | 「誰の何がどう変わるか」が冒頭で分かる。「毎回30分→5分」の形 |
| **メインポストに全ステップの目次** | 一覧だけで全体像がつかめる＝保存する価値が一目で分かる。スレッドを開かない人にも価値が残る |
| 1ステップ1ポスト＋番号 | 現在地が明確。各ポストに数字・操作・実例のどれかを必須化して「意識しよう」系の空文を排除 |
| ※でつまずき対処 | 実際にやる人だけが気付く情報＝実用の証明。保存の決め手 |
| 最初の一歩＋状況を聞く締め | 行動の敷居を下げ、リプライで読者の状況が集まる |

## プロンプト設計の判断

1. **目次型メインを必須化** — 旧版は「◯ステップで説明する」の予告のみ。実例研究では**目次そのもの**が保存を生む（メインだけで価値が完結）。
2. **「画面を見ながらそのまま実行できるか」を品質基準に** — 手順の粒度を「その日に1つ実行できる」から一段具体化。
3. **Web検索は正確性が必要な点だけ** — 操作名・設定値・価格。ノウハウの本体はbase_mdの経験・知見から書く。
