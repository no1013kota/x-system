## 参考にした実例・型（リサーチ 2026-09-01）

- **トレンドキーワードを含む投稿はタイムラインで優遇され、普段リーチできない層へ届く**（[MOMENTH](https://momenth.jp/content/x-trend)ほかトレンド解説記事で一致）。
- **視点ずらし型**: 「みんなは◯◯に注目しているが、本当のポイントは△△」— 多数派のなぞりは埋もれる。バズ投稿への独自見解の追加は元界隈へ拡散する（[addness 引用＋自分の視点型](https://addness.co.jp/media/twitter-imp/)）。
- **企業のトレンド便乗のNG**: 事故・災害・政治宗教への便乗、無関係な話題への強引な接続（炎上パターン記事で一致）。

## 構造分解

| 要素 | 効果 |
|---|---|
| 話題名・固有名詞を1行目に | 検索・トレンド面・おすすめ表示で拾われる（露出の入口） |
| 視点ずらしの一言 | 「なぞり」は数で埋もれる。切り口1つで引用・リプライの対象になる |
| 1ポスト完結 | 速さが価値。スレッドを組む時間で鮮度が落ちる |
| 中止条件 | 直近の話題と確認できなければ生成しない（古い話題への便乗は逆効果）。既存の仕組みを維持 |

## プロンプト設計の判断

1. **「本当のポイントは△△」の形を明記** — 旧版の「なぞりにしない」を、具体的な文型まで落とした。
2. **長文可でも短く** — Premium分岐で速報まで長文化しない逆指定（P-2と同じ判断）。
3. **話題名を1行目に置く指示を追加** — 露出の入口はキーワード一致。旧版には無かった。

## セルフレビュー

実AI生成による検証（T-M8-393・2026-09-01・$0.04〜0.05）:

- Web検索で実在の直近話題（ChatGPT Workのログインサイト対応／NVIDIA決算とメモリ供給）を自力で発見。1行目の固有名詞・視点ずらしは設計どおり。
- 問題1: 締めが説明文で終わる（会話が生まれない）→「最終文は問いか賛否の割れる言い切り。説明で終えない」を明記。
- 問題2: です・ます混入（base_mdは常体指定）→ SYSへ「base_mdの文体指定に全文で必ず従う」を追加。
- 残課題: 「セキュリティも大丈夫」のような大きすぎる保証が出る回があった（SYSの誇張禁止で概ね抑制されるが完全ではない）。
