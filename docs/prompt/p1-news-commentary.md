### 実例1: Claude Code 週次上限の改定（スレッド 4ポスト）

**メイン投稿**

```
【悲報】9月14日からClaude Codeの週次上限を恒久的に25%引き上げ。ただし今は期間限定で50%増なので、今日と比べると『実質17%のマイナス』　Anthropicが公式に表明。

書き方が分かりづらすぎる。。。
ヘビーユーザーにとっては悲報すぎる。。

・対象はPro / Max / Team / 席課金のEnterprise
・基準100なら今が150、9月14日から125
・発表ポストは引用1,500件超・返信1,700件超
・使用量の可視化と制御を強める変更も予告

↓詳細
```

**スレッド(2/4)**

```
(2/4)
Claude Codeの上限は2段構えだ。5時間ごとに戻るセッション枠と、週1回リセットの週次枠がある。この枠は http://claude.ai のチャットとも共通で、コード以外で使った分も残量を削る。

・セッション上限と週次上限は全モデル共通。/model で別モデルに逃げても回復しない
・Opus上限とSonnet上限はモデル系統ごと。この場合は /model で別系統に移れば続けられる
・残量は /usage で確認。d と w で直近24時間と7日間を切り替えられる
・v2.1.234以降は、リセットまで待って中断したタスクを自動で再開できる
```

**スレッド(3/4)**

```
(3/4)
では何が枠を食うのか。Claude Codeは毎リクエストで会話の全文を送り直している。朝から開きっぱなしのセッションに一言足すだけでも、その日の履歴まるごと分の重さがかかる。

・サブスクのキャッシュ寿命は1時間。休憩を挟んだ最初の一言は全履歴を読み直す
・スケジュールタスク、goalのチェックイン、他セッションからのメッセージは、放置中でも枠を削る
・エージェントチームはプランモードで約7倍のトークンを使う
・/compact は要約のために会話を読み込むので、それ自体が重い。用の済んだ話題は /clear で捨てる方がタダで速い
```

**スレッド(4/4)**

```
(4/4)
■ 補足
/usage には、スキル・サブエージェント・プラグイン・MCPサーバー別に、直近の使用量の内訳まで出る。長すぎるコンテキストやキャッシュミスが全体の10%以上を占めると警告が出るので、まず犯人を特定するのが先だ。ただし内訳は端末内のログから計算されるため、別のPCやhttp://claude.ai側の分は入らない。
止まりたくない場合は /usage-credits で追加購入できる。ただし追加クレジットを使い始めるとキャッシュ寿命が5分に落ちるので、TTLを自分で指定しない限り割高になりやすい。

■ 出典
https://x.com/ClaudeDevs/status/2093742321473065266
https://code.claude.com/docs/en/costs
```

## 構造分解（なぜこの形が伸びるか）

| 要素 | 実例での姿 | 効果 |
|---|---|---|
| 角括弧ラベル＋数字の1行目 | 【悲報】…25%…『実質17%のマイナス』 | 冒頭だけで「何が起きて自分にどう関係するか」が分かる。見かけと実質の差を**先に言い切る**のが独自価値 |
| 人の声の一言 | 「書き方が分かりづらすぎる。。。」 | 転載ではなく「この人の投稿」になる。共感の起点 |
| 箇条書き3〜5点 | 対象／基準100なら…／反応の規模／今後の予告 | 1行1事実。ここが**保存の理由**になる。読者が比べられる形へ数字を直している（基準100なら…）点が重要 |
| ↓詳細 | 最終行 | スレッドへの導線。読むかどうかを読者に委ねる |
| (2/4) 通し番号 | 続き全ポスト | 現在地が分かり離脱しにくい |
| 1ポスト1トピック | 仕組み→原因→補足 | 「仕組み（2段構え）」→「何が枠を食うか」→「対処（/usage・購入）」の順。**読者の疑問が湧く順** |
| ディテール保持 | /model・/usage・v2.1.234・TTL | コマンド名・バージョンまで書くから実用になる＝保存・引用される |
| ■ 補足／■ 出典 | 最終ポスト | 実用情報で締め、出典で信頼を担保（本アプリでは出典はsources経由で自動付加） |

## プロンプト設計の判断

1. **「基準100なら」の変換を手順に明記** — 実例1の最大の発明。%の入り組んだ発表を読者が暗算できる形へ直す。
2. **ラベルは「中身に合うものだけ（釣らない）」** — 【悲報】の乱用は信頼を削る。実質の判定（実質◯◯）とセットでのみ強い。
3. **感想の位置を固定** — 1行目の直後、箇条書きの前。ニュース→人の声→事実の順が実例の型。
4. **箇条書きの行数は3〜5** — 実例は4行。3未満は情報不足、6以上は目が滑る。
5. **出典はsourcesへ** — 実例は本文に出典URLを書くが、本アプリはSSRF検証済みURLを末尾ポストへ自動付加する既存機構に乗せる（プロンプトには「本文へ書かない」を維持）。
6. **品質基準を自己チェックとしてプロンプト末尾に置く** — 「メインだけで完結」「曖昧な行が無い」「保存されるディテール2つ以上」。
