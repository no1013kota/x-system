## 正本の関係

- **プロンプト本文の正本はコード**（`src/lib/prompts/gen-prompts.ts`）。全文の写しは[プロンプト設計書](../プロンプト設計書.md) §6 が持ち、スナップショットテストがコードの変更を検出する。

## 全パターン共通の設計原則

2026年時点のXアルゴリズムの公開情報・運用メディアの検証記事・運営者提供の実例から:

1. **保存（ブックマーク）が最強のシグナル。** 保存されるのは「あとで見返す理由」がある投稿＝数字・手順・固有名詞のディテールを持つ投稿。抽象論は保存されない。
2. **1行目がすべて。** タイムラインでは冒頭しか見えない。フックの型はSYS-GENに列挙（意外な数字・常識の否定・失敗談・見落とし指摘・対比・名指し・角括弧ラベル）。
3. **リプライが生まれる締め。** 「どう思いますか？」は答える気が起きない。読者が一言で自分の話をできる具体的な問いか、賛否を言いたくなる言い切りで締める。
4. **人の声を1つ入れる。** 「〜すぎる。。」のような素の感想が、情報の転載を「この人の投稿」に変える（運営者実例で最も効いている要素）。
5. **箇条書きは「・」で1行1事実。** 形容詞だけの行を作らない。メインポストの箇条書きが目次を兼ねると保存されやすい。
6. **ハッシュタグは使わない・URLは本文に書かない**（出典はアプリが sources 経由で末尾ポストへ付ける）。

## 文字数の方針（制限あり／なし）

**パターンを複製せず、アカウントの X Premium 加入（`x_accounts.x_premium`・T-M8-219）で自動分岐する**（T-M8-391）。

- Premium: 長文可。280への短縮も「読みやすさの240目標」も適用しない（長文プロンプトの成果物を壊さない）。上限25,000のみ。
- 非Premium: 従来どおり加重280以内（プロンプトへも `<pattern_rules>` の「文字数:」行で伝える）。

複製案（制限あり版・なし版の2パターンずつ）を採らなかった理由: 選択肢が倍になり選ぶ手間が増えるうえ、Xに投稿できるかはアカウント側の事実で決まる（利用者が選ぶ話ではない）。

## セルフレビューの記録

実生成（実AI・claude-sonnet-5・Web検索あり）で各パターンを評価→プロンプト改訂→再生成を3周実施した（T-M8-393・2026-09-01・実費 約$0.5）。記録は各パターンのファイル末尾「セルフレビュー」節。

3周から得た横断の学び:
1. **「〜を入れる」では揺れる。「この順で全部。欠けたら書き直す」まで書くと安定する**（P-1の4要素は2周目まで毎回どれかが欠けた）。
2. **スレッドの枠は使い切られる**。締めポスト（問い・最初の一歩・来週の注目）は「枠を予約する」形で明記しないと本文に食われる（P-3・P-6で発生）。
3. **文体はbase_mdに書いてあるだけでは守られない**。「出力前に読み直して全文で従う」をSYSに置いても混入は減るが零にはならない——完全な保証はコード側では不可能で、下書き確認と学習ループが最後の砦。
4. **事実の捏造はWeb検索があっても起きる**（実在不明の機能名・人名）。「確認できない具体名・数値を書かない」で減るが、ニュース系は sources の実在チェック（アプリ側SSRF検証）との併用が前提。
