## 参考にした実例・型（リサーチ 2026-09-01）

- **違和感の言語化型**: 「『休んだはずなのに疲れている』って、それもう休めてないよ。」— 誰もが薄々感じている違和感を明確な言葉にする。一文で完結し、スクロール中でも目に留まる（[socialbiz](https://socialbiz.jp/column/)の共感ポスト解説）。
- **意見表明型（仮説・持論）**: 体験から出した仮説を根拠付きで言い切る。賛否を呼ぶためインプレッションが伸びやすい。抽象論・両論併記では反応が出ない（[free-ai-tools 2026年版の型解説](https://free-ai-tools.jp/guide/x-post-writing-engagement)）。
- **運営者実例（実例2の締め）**: 「AIが論文を読む側から、実験を回す側へ。」— 対比の言い切りが意見の凝縮形。

## 構造分解

| 要素 | 効果 |
|---|---|
| 1行目の言い切り（賛否が分かれる立場） | どちらとも読める文は誰の心も動かさない。立場の明確さがリプライの燃料 |
| 理由1つ＋具体1つ | 根拠が1つあると「持論」になり、0だと「感想」で終わる。2つ以上は薄まる |
| 読者が立場を言いたくなる締め | 「あなたはどっち」を具体で聞く。汎用の「どう思いますか」は禁止（SYS-GEN共通） |
| 短さ | 意見は凝縮されているほど強い。長文可でも薄めて伸ばさない（**長文可＝長文必須ではない**） |

## プロンプト設計の判断

1. **「違和感の言語化」を型として明記** — 攻撃せずに賛否を生む最も安全で強い形。
2. **分量の逆指定** — 他パターンと違い「長文可の場合も短いままでよい」を明記（Premium分岐で意見文まで長文化する事故を防ぐ）。
3. **禁止事項は維持** — 人物・企業攻撃の禁止、反対の立場への敬意。炎上リスク管理はプロンプト層でも持つ。
4. **Web検索は「必要があれば・最大3回」**（2026-09-05・T-M8-442・要決定D-57） — 2026-09-01 の刷新時は「参考URLがあるときだけ・最大2回」だったが、運営者の指示で既定パターン6種すべてを「常に検索ツールを渡す・上限3回」に揃えた。「常に」はツールを渡す意味で、使うかどうかはモデルが必要（URLの内容確認・事実の裏取り）に応じて決める。意見の主材料は本人の視点（ベースmd）なので**検索を必須にはしない**（0回でも警告しない）。回数の数字はパターン設定（`<pattern_rules>`）が渡すので本文には書かない。出典方針は `with_url`（参考URLがあるときだけ `sources` へ入れる）のまま。設定値の正本は要件02 §3.23（`post_patterns` の seed）、パターン別の一覧はプロンプト設計書 §6 冒頭。

## セルフレビュー

実AI生成による検証（T-M8-393・2026-09-01・$0.004）:

- 1回目から高品質: 言い切り→具体の指示例→自分の失敗経験→逆説の結論→二択の問い、と設計どおり。
- 問題: 全角350字相当と長め（意見の凝縮としては上限ぎりぎり）→ プロンプトへ「全角350字程度まで」を明記。
- 残課題: モデルの世界知識由来の旧モデル名（GPT-4）が例に混ざることがある。実害は小さいが、学習ループ（PT-SUGGEST）での磨き込み対象。
