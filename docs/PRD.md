## 1. 背景・目的

### 1.1 背景

個人事業主にとって、Xでの継続的な発信は集客・信頼獲得の主要チャネルになっている。一方で、次のような課題がある。

- ネタ探し・情報収集・文章作成・画像作成・投稿・分析を毎日回すのは時間的負担が大きい
- SNS運用代行は月数万円〜と高額で、個人事業主には手が出しにくい
- 既存の予約投稿ツールは「投稿の作成」までは支援せず、汎用の生成AIチャットでは「自分らしさ」が出ない・毎回の指示が面倒

### 1.2 目的

Exos AIは、ユーザーの発信スタイルを学習したAIが、情報収集から投稿作成・投稿実行・分析改善までを自動化／半自動化し、**1日数分の確認だけで、自分らしい質の高いX運用を継続できる状態**をつくる。

### 1.3 プロダクトコンセプト

1. **ベースmdファイル方式**：学習・設定の結果をすべてXアカウント単位の「ベースmdファイル」（発信定義書）に集約し、これをすべての投稿生成の中核コンテキストとして使用する。上位プランではこのファイルとプロンプトを直接編集できる。
2. **BYOK方式＋おまかせの二段構え**：基本はX APIキー・生成AI APIキーをユーザー自身が登録するBYOK（Bring Your Own Key）方式とし、運営側のAPI原価を持たないことで月額500円の低価格を実現する。あわせて、キー登録が一切不要な**プレミアムプラン（運営キー同梱）**を用意し、セットアップの手間を避けたい層を取り込む。

## 2. ターゲットユーザー

### 2.1 プライマリターゲット

- 個人事業主・フリーランス（コンサルタント、士業、コーチ、講師、EC運営者、クリエイター等）
- Xを集客・認知獲得に使いたいが、運用に十分な時間を割けない
- ITリテラシーは中程度（手順ガイドがあればAPIキーの取得・登録ができる）。APIキー取得が難しいユーザーはプレミアムプランで受け止める

### 2.2 ペルソナ例

> 40代・個人コンサルタント。専門性は高いがX運用は不定期で、投稿が続かない。ネタや意見はあるが文章化に時間がかかる。ツール代は月1,000円程度なら払える。毎朝10分だけ下書きを確認して投稿する運用が理想。

### 2.3 MVPで想定しない利用

- 企業マーケチームによる複数人・承認フロー付きの運用
- 自動いいね・自動フォロー・自動リプライ等のエンゲージメント自動化（アカウント凍結リスクのため対象外）

## 3. スコープ

### 3.1 MVPでやること

- メール認証によるアカウント管理、X連携（OAuth）、APIキー登録（X／生成AI）
- 学習（参考アカウント・参考投稿・自分の過去投稿）と各種設定のベースmdファイルへの反映
- 運営側APIによる最新ニュース（AI・投資・SNS運用の3分野）の定期取得・表示・通知・ワンタップ投稿作成
- 6種の投稿パターンによる投稿生成＋画像生成（ChatGPT／Gemini選択式）。うち引用ポスト（P-5）はfeature flagで初期提供停止
- スケジュールによる自動運用（下書きまで／自動投稿の選択）と下書き管理
- 投稿実績の表示・分析・改善提案（表示のみ。ベースmdへの自動反映は行わない）
- 3プラン（500円／1,000円／2,980円・税込）のサブスクリプション課金と7日間無料トライアル

### 3.2 MVPでやらないこと（将来検討）

- セルフサービスのアカウント削除機能（法令上必要な個別の請求は問い合わせ窓口で運営対応）
- 自動リプライ・自動いいね・自動フォロー
- チーム利用・承認ワークフロー
- 他SNS対応（Threads、Instagram等）
- ネイティブアプリ（Webアプリケーションとして提供。スマホはレスポンシブ対応まで）
- 動画生成
- メール・アプリ内以外の通知チャネル（LINE等）

## 4. 主要ユーザーフロー

1. **初回セットアップ（専用オンボーディング画面は持たない）**
   - 共通：アカウント作成 → カード登録（トライアル開始）→ 以降は設定画面から任意の順に初期設定を行う。前提が不足したまま生成・投稿を実行した場合は、不足項目と設定画面への遷移ボタンをエラーとして表示し、ホームには不足項目のチェックリスト（初期設定ガイド）を表示する
   - BYOKプラン（通常／md）：X APIキー登録 → X連携（OAuth・ユーザー自身のDeveloper App経由。APIキー登録が先） → 生成AI APIキー登録 → ペルソナ・テーマ・トンマナ・NG設定（保存時にベースmdファイル自動生成） → （任意）学習（参考アカウント／参考投稿／自分の過去投稿の取り込み）
   - プレミアムプラン：X連携（OAuth・運営のDeveloper App経由） → ペルソナ・テーマ・トンマナ・NG設定（保存時にベースmdファイル自動生成） → （任意）学習（APIキー登録は不要）

2. **日常運用（半自動）**
   ニュース通知を受け取る → 「すぐに投稿作成」 → 生成されたスレッドを確認・編集 → 投稿 or 下書き保存

3. **自動運用**
   自動投稿の内容と停止方法を確認して明示同意 → スケジュール（投稿パターン × 時間 × 下書き/投稿）を設定 → 定時に自動リサーチ・生成 → 「下書きまで」設定なら通知を受けて確認・投稿、「自動投稿」設定ならそのまま投稿。自動投稿の同意撤回は即時反映する

4. **改善提案**
   投稿実績を自動取得 → ユーザーの「提案を更新」操作で型×時間帯×テーマの観点から分析し、根拠つきの改善提案を提示 → ユーザーが内容を確認し、必要に応じて発信テーマ・トンマナ等の設定変更やベースmd編集（md/プレミアム）で自ら反映する

### 5.3 最新ニュース確認

ニュースの取得はユーザーのAPIキーではなく、**運営側の生成AI APIによるWebリサーチ**で行い、結果を全ユーザーに共通配信する。

| ID | 機能 | 説明 | 優先度 |
|---|---|---|---|
| N-1 | ニュース自動取得（運営側） | **AI・投資・SNS運用**の3分野を対象に、**日本時間10:00〜20:00・2時間間隔**（10/12/14/16/18/20時）で運営側APIがWebリサーチを実行し、要約・インパクト判定のうえ全ユーザーへ配信。各回は直近3時間分（初回10:00は前日20:00以降を埋める14時間分）を重ねて取得し、一部の起動が失敗しても後続回が取得漏れを補う。**取得対象の分野は実費に直結する**ため、利用者が選べる分野もこの3分野に揃える | Must |
| N-2 | 最新ニュース一覧表示 | 分野別（**取得対象の3分野**）に最新ニュースを一覧表示（既定で過去7日分）。表示項目：カテゴリー／要約／遷移先URL／インパクト（高・中・低）。表示件数・表示する分野はユーザーが設定可能 | Must |
| N-3 | ニュース通知 | 設定した分野・インパクトに該当する新着ニュースを、JST 9:00〜20:00の取得時刻ごとに1件の時間単位ダイジェストとして通知。該当0件の時間帯は通知しない | Must |
| N-4 | すぐに投稿作成ボタン | ニュースカードから1タップで「ニュース解説（スレッド付き）」の生成を開始。生成はプランに応じたキー（BYOK／運営キー）で実行 | Must |

### 5.4 投稿パターン選択・投稿作成

**共通仕様**

- 有効化後のP-5で必須とする引用対象URLを除き、入力項目は任意。未入力の場合はベースmd＋発信テーマに基づき自動でリサーチ・生成する
- スレッドは「1ポスト目（フック）＋解説ポスト群」の連投形式で出力
- 生成結果は投稿前に編集・追加指示付き再生成が可能。文字数超過は自動チェック
- 生成に使うキーはプランに応じて切替（BYOKプラン＝ユーザー登録キー／プレミアムプラン＝運営キー）。リサーチには各社のWeb検索機能を利用

| ID | パターン | 入力 | 出力 | 優先度 |
|---|---|---|---|---|
| P-1 | ニュース解説 | 参考URL、追加指示文 | 関連リサーチ＋要点＋解説スレッド | Must |
| P-2 | 自分の考え・意見投稿 | 参考URL、自分の考え、追加指示文 | 本文（単発ポスト） | Must |
| P-3 | ノウハウ・ハウツー投稿 | 参考URL、追加指示文 | 関連リサーチ＋要点＋解説スレッド | Must |
| P-4 | トレンド便乗投稿 | 参考URL、追加指示文 | トレンドリサーチ＋要点＋解説スレッド | Must |
| P-5 | 引用ポスト投稿 | 引用したい投稿URL、追加指示文 | 1ポスト目を対象URL付きの通常投稿として送信し、必要な補足をreplyで連結する | 初期提供停止 |
| P-6 | 週次まとめ | 追加指示文 | 1週間分のリサーチ＋要点＋まとめスレッド | Must |
| P-7 | 画像生成オプション | P-1〜P-6の生成本文 | スレッド1ポスト目に添付する画像1枚。OpenAI／Geminiから選択、再生成可 | Must |

P-5は将来提供用の仕様として保持するが、v1.0初期リリースは`FEATURE_QUOTE_POST_ENABLED=false`として利用者へ提供しない。有効化前に、X APIで取得した対象ポスト本文をLLM入力へ渡す契約とその検証を完成させる。有効化後もX Enterprise限定の`quote_tweet_id`を投稿APIへ渡さず、1ポスト目の本文末尾へ対象X URLをコードで付与して通常投稿として送信する。2ポスト目以降は直前の自分のtweet_idへのreplyとする。

### 5.5 投稿実行・スケジュール（自動運用）

スケジュール枠（スロット）単位で「どのパターンを・いつ・どこまで自動で」実行するかを設定する。定時になるとリサーチ＋生成（リサーチ＋要点＋解説スレッド）が自動実行される。

| ID | 機能 | 説明 | 優先度 |
|---|---|---|---|
| S-1 | 投稿内容設定 | スロットごとに追加指示文を保存し、定時実行時の生成に使用 | Must |
| S-2 | 投稿時間設定 | 曜日×時刻で実行タイミングを指定（複数スロット登録可）。時刻は**9:00〜22:00・30分刻み** | Must |
| S-3 | 下書き／自動投稿の切替 | スロットごとに「下書きまで（要確認）」or「そのまま投稿」を選択。初めて自動投稿を有効にする際は、対象操作を説明して明示同意を取得する。設定から即時opt-outでき、停止後は自動投稿を実行しない | Must |
| S-4 | 投稿パターン設定 | スロットごとに使用する投稿パターン（P-1〜P-4/P-6）と画像生成の有無を割り当て。引用対象が毎回必要なP-5は手動生成のみ | Must |
| S-5 | 下書き管理 | 未投稿下書きの一覧・編集・削除・投稿ボタン。下書き作成時に通知 | Must |
| S-6 | 投稿履歴 | 投稿成功した下書きを物理削除せず履歴へ移し、いつ・何を・自動／手動どちらで投稿したかとtweet_idsを保持する。障害時の切り分けにも使用 | Should |

### 5.6 分析・改善

| ID | 機能 | 説明 | 優先度 |
|---|---|---|---|
| K-1 | 投稿別実績表示 | tweet_id単位で各ポストのインプレッション／いいね／リポスト／プロフィールアクセス数を表示（スレッドはポスト別内訳＋合算）。取得不能値は0と区別し、非公開指標はX APIの取得可能期間内で更新 | Must |
| K-2 | 分析・改善提案 | ユーザーの「提案を更新」操作（分析画面）を起点に、どの型×時間帯×テーマが伸びたかを分析し（テーマは対象投稿の本文からAIが判断）、根拠（該当投稿・数値）つきの改善提案を提示。実行は1日1回まで。提案は**表示専用**とし、ベースmd・プロンプトへの自動反映は行わない（ユーザーが設定変更やmd編集〔md/プレミアム〕で自ら反映する） | Must |

## 8. 技術前提・制約

### 8.1 X API

- X API v2のPay-Per-Use・credit方式を前提とする。endpoint別の価格は変動し、最新値はDeveloper Consoleで確認する
- BYOKユーザーには「開発者登録 → App作成・callback URL設定 → credit/予算設定 → Client ID等の登録」の取得手順ガイド（キー登録画面内）が必要
- 投稿、読み取り、media uploadはOAuth 2.0 user contextで実行し、`tweet.read tweet.write users.read media.write offline.access`を要求する
- OAuth 2.0 user contextは、利用者が認可した運営Developer Appからも本人の代理で投稿できる。運営Appのapp-only credentialだけで投稿するのではなく、利用者ごとに発行されたaccess/refresh tokenを使う。したがってプレミアムでは利用者自身のDeveloper App登録を必須にしない
- OAuth認可だけでは自動操作への十分な同意にならないため、「どの投稿を、どの条件で自動実行するか」を説明した明示同意を別途取得し、設定からの停止を即時反映する。用途を大きく変更した場合は再同意を求める
- 投稿文字数はXの加重文字数280以内とし、公式`twitter-text`互換で検証する。URLは固定長、CJK・絵文字は重み付きで数える
- feature flag有効化後のP-5は`quote_tweet_id`を投稿APIへ渡さず、対象X URLを1ポスト目の本文末尾へ付けた通常投稿として送信する。threadは直前の自分のtweet_idへのreply、画像は事前に`POST /2/media/upload`して得たmedia idで送信する
- tweet_id別実績はpublic metricsと、所有投稿で取得可能なnon-public metricsを使う。non-public metricsは投稿後30日以内というAPI制約を前提にする
- 残高不足はサービス側から検知しづらいため、投稿失敗時に「Xクレジット残高の確認」を促すエラーメッセージを実装する
- **プレミアムプラン**のX投稿・読み取りは運営のDeveloper App経由で行い、X API費用は運営負担（月間利用上限の設計に反映済み）
- 料金・仕様は変更が頻繁なため、リリース前および定期的に[X API公式ドキュメント](https://docs.x.com/)とDeveloper Consoleで再確認する

### 8.2 生成AI API

- 文章生成・分析・リサーチはClaude／OpenAI／Geminiのいずれでも動作すること
- **画像生成はChatGPT（OpenAI）／Geminiの選択式**。Claudeは画像生成非対応のため、BYOKプランでOpenAI・Geminiがともに未登録の場合は画像生成機能を非活性にする
- リサーチ（Web検索）は各社の検索機能（Claudeのweb search／OpenAIのweb search／GeminiのGoogle検索グラウンディング）を利用
- **プレミアムプラン**では文章生成・リサーチに運営側のClaude APIキー、画像生成に運営側のOpenAIまたはGeminiキーを使う。Claudeの具体的な軽量モデルは環境変数で指定し、AI部分の単価と品質をβで計測する。X投稿費を含む総原価1,000円以内は保証条件ではなく運用目標として監視する
- ニュース収集（8.3）のみ、プランを問わず運営側Claudeキーで実行する（全ユーザー共通配信のため。上限カウント対象外）。それ以外の文章AI実行（改善提案の生成を含む）は「BYOK＝ユーザー選択キー／プレミアム＝運営Claudeキー」に統一する。改善提案はユーザーの明示的な操作を起点にのみ実行されるため、本人の操作なしにキーが消費されることはない

### 8.3 その他

- **ニュース収集（運営側共通基盤）**：ユーザーのAPIキーは使用せず、運営側の生成AI APIによるWebリサーチで実行する。対象は**AI・投資・SNS運用の3分野**、**日本時間10:00〜20:00に2時間間隔**で分野ごとにリサーチし（各回は直近3時間分を重ねて取得し、初回10:00は前日20:00以降を埋める14時間分を取得する。窓は起動間隔より広く、一部起動の失敗は後続回が補う）、要約・カテゴリ分類・インパクト判定のうえ全ユーザーへ共通配信する。UIは既定で過去7日分を表示する。実行回数は3分野×6回/日で固定のため、運営側コストはユーザー数に依存せず予測可能。**発信テーマ（L-5）は6テーマのままで、ニュース分野と1対1に対応するのは取得対象の3分野のみ**（テーマは生成の方向づけにも使うため縮小しない）
- **スケジューラ**：利用者が設定する投稿スロットは**JST 9:00〜22:00・30分刻み**。`scheduler_tick`は5分間隔で起動し（初期は常時稼働Macのlaunchd、運用条件到達後は同じAPI RouteをVercel Cronから起動）、スロット定刻の起動が該当ジョブを「1ジョブ = 1 Function呼び出し」で即時実行へdispatchする。生成→画像→投稿の各段も個別Functionへ連鎖dispatchし、自動投稿は定刻から概ね5分以内に完了する。実行状態はDBキューで管理し、通知・期限切れデータの回収もtickが行う
- **ベースmdファイル**：Xアカウントごとに1ファイル。学習結果・設定をセクション構造で保持し、生成時にシステムプロンプトへ組み込む

## 10. リスクと対策

| リスク | 対策 |
|---|---|
| APIキー登録のつまずきによる離脱（BYOKプラン） | スクリーンショット付き取得ガイド、登録時の疎通チェック、わかりやすいエラーメッセージ。難しいユーザーにはプレミアムプランを案内 |
| X APIの料金・仕様変更 | BYOKプランは運営原価への直接影響なし。プレミアムプランは原価変動を受けるため、利用上限値・価格の定期見直し条項を規約に用意 |
| Xクレジット残高切れで自動投稿が停止（BYOKプラン） | 投稿失敗時に残高確認を促す通知。将来的には残高低下の予兆検知を検討 |
| 運営側APIコストの増加（ニュース基盤・プレミアムプラン） | 通常投稿・URL付き投稿・文章・画像の4枠で制御し、外部API利用をユーザー別に記録する。月1,000円目標を超え得るため、β実測に基づき価格と上限を見直す |
| 生成品質への不満 | デフォルトを「下書きまで」モードに設定。下書き承認率をモニタリングし、プロンプト・ベースmd改善へ反映 |
| 誤った学習によるベースmdの劣化 | ベースmdの全変更を履歴化し、学習ソースの削除で該当知見を除去できる。md/プレミアムは編集履歴からロールバック可能。改善提案は自動反映しない（表示専用） |
| 誤情報の投稿 | ニュース解説・まとめ系には出典URLを含める。NG設定の適用と投稿前チェック |
| アカウント凍結リスク | 1 Xアカウントあたり日次50ポストで停止し、エンゲージメント自動化機能は実装しない |
| APIキーの漏洩 | 暗号化保存・マスク表示・即時削除導線 |
