# ADR-0007: タイプスケールとタップ対象寸法の規約

| 項目 | 内容 |
|---|---|
| ステータス | 採用 |
| 日付 | 2026-08-08 |
| 関連 | ADR-0006（UIデザイン基盤）、T-M8-70 / T-M8-71、`src/components/ui/type-scale.test.ts` |

## 背景

利用者から「ボタン・フォントの大きさに改善余地はあるか」の問いを受け、全コンポーネントを実測した。

- フォントサイズが**21種**（10〜48px）直書きされ、12/12.5/13/13.5/14pxの5段が約380箇所で併存。
  同じ「カードの説明文」役割に4サイズが混在していた（旧shadcn世代とT-M8リデザイン世代の二重体系）。
- 補足文の `--ink-3`（rgba(0,0,0,0.45)）は白地でコントラスト比3.36:1しかなく、WCAG 1.4.3（AA=4.5:1）に
  全32箇所が不適合。しかも全て15px以下＝「最小の字が最も薄い」状態だった。
- 入力欄38箇所中37箇所がfont-size16px未満で、iOS Safariではフォーカスのたびに自動ズームが発生。
- shadcn既定のボタン高（default=32px / sm=28px）は、最頻出のsmがWCAG 2.5.8（24px）ぎりぎりで、
  下書きの「投稿/破棄」のような不可逆操作の並びに16〜20px不足（HIG 44pt / Material 48dp基準）。

## 決定

1. **本文系のフォントサイズは3段だけ**: `text-caption`(12px)＝メタ情報・注記／`text-body`(13px)＝UI本文・
   ラベル／`text-sm`(14px)＝フォーム・テーブル。トークンは `globals.css` の `@theme`（`--text-caption` /
   `--text-body`）。見出し系は 15px（カードタイトル）/20px（h1）/22・26px（認証・マーケ）を任意値で許す。
   **15px未満の任意値（`text-[12.5px]`等）は `type-scale.test.ts` が禁止**。装飾の11pxはバッジ・
   未読数ドット・モバイル下部ナビのラベルのみ許可（同テストの許可リスト）。
2. **`cn()` はカスタムサイズを登録した tailwind-merge を使う**（`src/lib/utils.ts`）。素のtwMergeは
   `text-body` を文字色と誤分類し、色クラスと並ぶと**サイズ指定が黙って消える**（実際に発生した）。
3. **薄文字の下限**: `--ink-3` は rgba(0,0,0,0.56)（白地で約4.6:1）。これよりも薄い文字色を足さない。
4. **ボタン高の基準**（`components/ui/button.tsx`）: sm=32px / default=36px / lg=40px。主要CTA
   （認証・決済・保存）は呼び出し側で `min-h-11`(44px)。テキストリンクをタップ対象にする場合は
   `py-2 -my-2` 等で**見た目を変えずに当たり判定を24px以上**にする。素のcheckbox/radioは `size-4` を
   付け、**ラベル全体を `min-h-9`以上のタップ対象**にする。
5. **入力欄のiOSズーム対策は globals.css の無層メディアクエリ1本**（モバイル幅で入力系のみ16px）。
   個別クラスで対応しない（付け忘れが必ず出る）。再発は `mobile-layout.spec.ts` が実font-sizeで検査。

## 結果

- 主要な原則との対応: WCAG 1.4.3（コントラスト）・2.5.8（ターゲット最小24px）に適合。44px（AAA/HIG）は
  PC中心の管理画面として全面適用せず、認証・決済・モバイル下部ナビ（64px）など要所のみ。
- 新しいサイズを追加したくなったら、この3段＋見出し系で表現できないかを先に検討する。
  どうしても必要なら本ADRを更新し、`type-scale.test.ts` の許可リストへ理由付きで足す。
