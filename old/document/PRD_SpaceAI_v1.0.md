## 1. 背景・目的

### 1.1 背景

個人事業主にとって、Xでの継続的な発信は集客・信頼獲得の主要チャネルになっている。一方で、次のような課題がある。

- ネタ探し・情報収集・文章作成・画像作成・投稿・分析を毎日回すのは時間的負担が大きい
- SNS運用代行は月数万円〜と高額で、個人事業主には手が出しにくい
- 既存の予約投稿ツールは「投稿の作成」までは支援せず、汎用の生成AIチャットでは「自分らしさ」が出ない・毎回の指示が面倒

### 1.2 目的

Space AIは、ユーザーの発信スタイルを学習したAIが、情報収集から投稿作成・投稿実行・分析改善までを自動化／半自動化し、**1日数分の確認だけで、自分らしい質の高いX運用を継続できる状態**をつくる。

### 1.3 プロダクトコンセプト

1. **ベースmdファイル方式**：学習・設定の結果をすべてXアカウント単位の「ベースmdファイル」（発信定義書）に集約し、これをすべての投稿生成の中核コンテキストとして使用する。上位プランではこのファイルとプロンプトを直接編集できる。
2. **BYOK方式＋おまかせの二段構え**：基本はX APIキー・生成AI APIキーをユーザー自身が登録するBYOK（Bring Your Own Key）方式とし、運営側のAPI原価を持たないことで月額500円の低価格を実現する。あわせて、キー登録が一切不要な**プレミアムプラン（運営キー同梱）**を用意し、セットアップの手間を避けたい層を取り込む。

## 2. ターゲットユーザー

### 2.1 プライマリターゲット

- 個人事業主・フリーランス（コンサルタント、士業、コーチ、講師、EC運営者、クリエイター等）
- Xを集客・認知獲得に使いたいが、運用に十分な時間を割けない
- ITリテラシーは中程度（手順ガイドがあればAPIキーの取得・登録ができる）。APIキー取得が難しいユーザーはプレミアムプランで受け止める

### 2.2 ペルソナ例

> 40代・個人コンサルタント。専門性は高いがX運用は不定期で、投稿が続かない。ネタや意見はあるが文章化に時間がかかる。ツール代は月1,000円程度なら払える。毎朝10分だけ下書きを確認して投稿する運用が理想。

### 2.3 MVPで想定しない利用

- 企業マーケチームによる複数人・承認フロー付きの運用
- 自動いいね・自動フォロー・自動リプライ等のエンゲージメント自動化（アカウント凍結リスクのため対象外）

## 3. スコープ

### 3.1 MVPでやること

- メール認証によるアカウント管理、X連携（OAuth）、APIキー登録（X／生成AI）
- 学習（参考アカウント・参考投稿・自分の過去投稿）と各種設定のベースmdファイルへの反映
- 運営側APIによる最新ニュース（AI・Web3・投資の3分野）の定期取得・表示・通知・ワンタップ投稿作成
- 6種の投稿パターンによる投稿生成＋画像生成（ChatGPT／Gemini選択式）
- スケジュールによる自動運用（下書きまで／自動投稿の選択）と下書き管理
- 投稿実績の表示・分析・改善提案・承認制の学習ループ
- 3プラン（500円／1,000円／2,980円・税込）のサブスクリプション課金と7日間無料トライアル

### 3.2 MVPでやらないこと（将来検討）

- 自動リプライ・自動いいね・自動フォロー
- チーム利用・承認ワークフロー
- 他SNS対応（Threads、Instagram等）
- ネイティブアプリ（Webアプリケーションとして提供。スマホはレスポンシブ対応まで）
- 動画生成
- メール・アプリ内以外の通知チャネル（LINE等）

## 4. 主要ユーザーフロー

1. **初回セットアップ**
   - BYOKプラン（通常／md）：アカウント作成 → カード登録（トライアル開始） → X APIキー登録 → X連携（OAuth） → 生成AI APIキー登録 → 学習（参考アカウント／参考投稿／自分の過去投稿の取り込み） → ペルソナ・テーマ・トンマナ・NG設定 → ベースmdファイル自動生成
     ※OAuth認可はユーザー自身のDeveloper App経由で行う（APIキー登録が先）
   - プレミアムプラン：アカウント作成 → カード登録 → X連携（OAuth・運営のDeveloper App経由） → 学習・各種設定 → ベースmdファイル自動生成（APIキー登録は不要）

2. **日常運用（半自動）**
   ニュース通知を受け取る → 「すぐに投稿作成」 → 生成されたスレッドを確認・編集 → 投稿 or 下書き保存

3. **自動運用**
   スケジュール（投稿パターン × 時間 × 下書き/投稿）を設定 → 定時に自動リサーチ・生成 → 「下書きまで」設定なら通知を受けて確認・投稿、「自動投稿」設定ならそのまま投稿

4. **改善ループ（承認制）**
   投稿実績を自動取得 → 分析・改善提案を根拠つきで提示 → ユーザーがワンタップで承認 → 承認された知見のみベースmdへ反映 → 次回以降の生成品質が向上

学習・設定の結果はすべてXアカウント単位の**ベースmdファイル**に構造化して書き込まれ、以後すべての投稿生成のコンテキストとして使用される。

| L-2 | 参考投稿学習 | 伸びた投稿のURLを個別登録し、伸びた理由・型を分析して反映 | Must |
| L-3 | 自分の過去投稿の取り込み | 連携済みアカウントの過去投稿を取り込み、語彙・口癖・視点など「自分らしさ」を抽出して反映 | Must |
| L-4 | ペルソナ設定 | 「誰として」「誰に向けて」発信するかを設定 | Must |
| L-5 | 発信テーマ・ジャンル設定 | 複数選択＋自由入力（例：Web3、マーケティング）。投稿生成・リサーチの方向づけに使用（ニュース分野はAI・Web3・投資の3分野固定で、本設定とは独立） | Must |
| L-6 | トーン＆マナー設定 | ですます調／断定調、絵文字の有無、ハッシュタグ方針など | Must |
| L-7 | NG設定 | やらないこと・NGワード・NGトピックを登録。すべての生成に適用し、投稿前チェックにも使用 | Must |
| L-8 | ベースmdの更新 | 学習ソースの追加・削除・設定変更時にベースmdへ差分反映 | Must |

### 5.3 最新ニュース確認

ニュースの取得はユーザーのAPIキーではなく、**運営側の生成AI APIによるWebリサーチ**で行い、結果を全ユーザーに共通配信する。

| N-1 | ニュース自動取得（運営側） | **AI・Web3・投資**の3分野を対象に、**日本時間9:00〜20:00・1時間間隔**で運営側APIがWebリサーチを実行し、要約・インパクト判定のうえ全ユーザーへ配信 | Must |
| N-2 | 最新ニュース一覧表示 | 分野別（AI／Web3／投資）に最新ニュースを一覧表示。表示項目：カテゴリー／要約／遷移先URL／インパクト（高・中・低）。表示件数・表示する分野はユーザーが設定可能 | Must |

| N-4 | すぐに投稿作成ボタン | ニュースカードから1タップで「ニュース解説（スレッド付き）」の生成を開始。生成はプランに応じたキー（BYOK／運営キー）で実行 | Must |

### 5.4 投稿パターン選択・投稿作成

**共通仕様**

- 入力項目はすべて任意。未入力の場合はベースmd＋発信テーマに基づき自動でリサーチ・生成する
- スレッドは「1ポスト目（フック）＋解説ポスト群」の連投形式で出力
- 生成結果は投稿前に編集・追加指示付き再生成が可能。文字数超過は自動チェック
- 生成に使うキーはプランに応じて切替（BYOKプラン＝ユーザー登録キー／プレミアムプラン＝運営キー）。リサーチには各社のWeb検索機能を利用

| ID | パターン | 入力 | 出力 | 優先度 |
|---|---|---|---|---|
| P-1 | ニュース解説 | 参考URL、追加指示文 | 関連リサーチ＋要点＋解説スレッド | Must |
| P-2 | 自分の考え・意見投稿 | 参考URL、自分の考え、追加指示文 | 本文（単発ポスト） | Must |
| P-3 | ノウハウ・ハウツー投稿 | 参考URL、追加指示文 | 関連リサーチ＋要点＋解説スレッド | Must |
| P-4 | トレンド便乗投稿 | 参考URL、追加指示文 | トレンドリサーチ＋要点＋解説スレッド | Must |
| P-5 | 引用リポスト投稿 | 引用したい投稿URL、追加指示文 | 要点＋解説スレッド（引用ポスト形式で投稿） | Must |
| P-6 | 週次まとめ | 追加指示文 | 1週間分のリサーチ＋要点＋まとめスレッド | Must |
| P-7 | 画像生成 | 投稿文章 | 投稿に添付する画像。生成エンジンはChatGPT（OpenAI）／Geminiから選択式。再生成可 | Must |

| ID | 機能 | 説明 | 優先度 |
|---|---|---|---|
| S-1 | 投稿内容設定 | スロットごとに追加指示文を保存し、定時実行時の生成に使用 | Must |
| S-2 | 投稿時間設定 | 曜日×時刻で実行タイミングを指定（複数スロット登録可） | Must |
| S-3 | 下書き／自動投稿の切替 | スロットごとに「下書きまで（要確認）」or「そのまま投稿」を選択 | Must |
| S-4 | 投稿パターン設定 | スロットごとに使用する投稿パターン（P-1〜P-6）と画像生成の有無を割り当て | Must |
| S-5 | 下書き管理 | 下書きの一覧・編集・削除・投稿ボタン。下書き作成時に通知 | Must |
| S-6 | 投稿履歴 | いつ・何を・自動／手動どちらで投稿したかのログ。障害時の切り分けにも使用 | Should |

## 6. 料金プラン

**表示価格はすべて税込。**

| | 通常プラン | mdプラン | プレミアムプラン |
|---|---|---|---|
| 月額（税込） | 500円 | 1,000円 | 2,980円 |
| APIキーの用意（X・生成AI） | 必要（BYOK） | 必要（BYOK） | **不要（運営キーで動作）** |
| 基本機能（5.1〜5.6、5.8） | ○ | ○ | ○ |
| mdファイル・プロンプト編集（5.7） | − | ○ | ○ |
| 連携Xアカウント数 | 1 | 3 | 3（利用上限は合算） |

- **無料トライアル**：全プラン対象、7日間。登録時にカード登録が必須（Stripe／Link）。トライアル中は選択したプランの機能範囲・利用上限をそのまま適用（プレミアムプランの上限もトライアル中・トライアル後で同一）。期間終了後は選択プランで自動課金開始（期間中に解約すれば課金なし）
- **決済**：実装容易性を最優先し、**Stripeホスト型Checkout（サブスクリプションモード）＋Webhook＋カスタマーポータル**で構成する。トライアルはStripeの`trial_period_days`を利用。自前のカード入力フォームは実装しない
- **ユーザー側の別途負担（BYOKプランのみ）**：X APIの利用料（従量課金・後述）、生成AI APIの従量課金。LP・登録画面で必ず明示する。プレミアムプランではAPI費用の追加負担なし

## 7. 非機能要件（MVPレベル）

- **提供形態**：Webアプリケーション（インストール不要）
- **セキュリティ**：APIキー・トークンは暗号化して保存。画面上はマスク表示（末尾4桁のみ）。キーの差し替え・削除導線を用意
- **信頼性**：自動投稿失敗時はリトライ（例：2回）＋ユーザー通知。同一コンテンツの二重投稿を防止（冪等性の担保）
- **パフォーマンス**：投稿生成（リサーチ含む）は目安60〜90秒以内。生成中はプログレス表示
- **対応環境**：PCブラウザ（Chrome／Safari／Edge最新）。スマホはレスポンシブで閲覧＋下書き確認・投稿操作が可能
- **規約・法令**：X Developer Agreement／自動化ルールを遵守。生成コンテンツの内容と投稿の最終責任はユーザーにあることを利用規約に明記

## 8. 技術前提・制約

### 8.1 X API

- 2026年2月以降、X APIは新規アカウントに対して**従量課金制（Pay-Per-Use）**に移行済み。新規作成アプリは必ず従量課金となる
- 前払いクレジット制（$5〜購入可）。支出上限の設定が可能で、残高切れ時はAPIが停止する仕組み
- 単価の目安：投稿作成 $0.010/回、投稿読み取り $0.005/回、分析読み取り $0.005/回、フォロー/フォロワー読み取り $0.010/回 ほか
- コスト試算例（BYOK）：毎日5ポストのスレッド1本＋実績取得を行った場合、月間およそ$2〜4（数百円）程度の想定。**スレッドは1ポスト＝1課金**である点に注意
- BYOKユーザーには「開発者登録 → 従量課金アプリ作成 → クレジット購入 → キー登録」のオンボーディングガイド（スクリーンショット付き）が必須
- 残高不足はサービス側から検知しづらいため、投稿失敗時に「Xクレジット残高の確認」を促すエラーメッセージを実装する
- **プレミアムプラン**のX投稿・読み取りは運営のDeveloper App経由で行い、X API費用は運営負担（月間利用上限の設計に反映済み）
- 料金・仕様は変更が頻繁なため、リリース前および定期的に公式情報（developer.x.com）で再確認する

### 8.2 生成AI API

- 文章生成・分析・リサーチはClaude／OpenAI／Geminiのいずれでも動作すること
- **画像生成はChatGPT（OpenAI）／Geminiの選択式**。Claudeは画像生成非対応のため、BYOKプランでOpenAI・Geminiがともに未登録の場合は画像生成機能を非活性にする
- リサーチ（Web検索）は各社の検索機能（Claudeのweb search／OpenAIのweb search／GeminiのGoogle検索グラウンディング）を利用
- **プレミアムプラン**では文章生成・リサーチ・画像生成とも運営側キーで実行する。利用モデルは、原価目標（1ユーザーあたり月1,000円以内）を満たす運営指定の軽量モデルとする

### 8.3 その他

- **ニュース収集（運営側共通基盤）**：ユーザーのAPIキーは使用せず、運営側の生成AI APIによるWebリサーチで実行する。対象は**AI・Web3・投資の3分野固定**、**日本時間9:00〜20:00に1時間間隔**で分野ごとにリサーチし、要約・カテゴリ分類・インパクト判定のうえ全ユーザーへ共通配信する。実行回数は最大3分野×12回/日で固定のため、運営側コストはユーザー数に依存せず予測可能
- **スケジューラ**：スロット実行はジョブキューで管理し、失敗時の再実行・通知を行う
- **ベースmdファイル**：Xアカウントごとに1ファイル。学習結果・設定・承認済みの分析知見をセクション構造で保持し、生成時にシステムプロンプトへ組み込む

## 10. リスクと対策

| リスク | 対策 |
|---|---|
| APIキー登録のつまずきによる離脱（BYOKプラン） | スクリーンショット付き取得ガイド、登録時の疎通チェック、わかりやすいエラーメッセージ。難しいユーザーにはプレミアムプランを案内 |
| X APIの料金・仕様変更 | BYOKプランは運営原価への直接影響なし。プレミアムプランは原価変動を受けるため、利用上限値・価格の定期見直し条項を規約に用意 |
| Xクレジット残高切れで自動投稿が停止（BYOKプラン） | 投稿失敗時に残高確認を促す通知。将来的には残高低下の予兆検知を検討 |
| 運営側APIコストの増加（ニュース基盤・プレミアムプラン） | ニュースは実行回数固定で予測可能。プレミアムプランは月間利用上限で1ユーザーあたり原価を約930円以下に管理し、実測に基づき上限値・単価前提を見直し |
| 生成品質への不満 | デフォルトを「下書きまで」モードに設定。下書き承認率をモニタリングし、プロンプト・ベースmd改善へ反映 |
| 誤った学習によるベースmdの劣化 | 学習ループは承認制（K-3）。反映履歴とロールバックで復元可能にする |
| 誤情報の投稿 | ニュース解説・まとめ系には出典URLを含める。NG設定の適用と投稿前チェック |
| アカウント凍結リスク | 投稿頻度の上限ガード（例：1日あたり上限件数）、エンゲージメント自動化機能は実装しない |
| APIキーの漏洩 | 暗号化保存・マスク表示・即時削除導線 |
