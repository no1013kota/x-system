# add-task：要望をバックログのタスクに変える

利用者の言葉（「〜したい」「〜が使いにくい」「〜が動かない」）を受け取り、**着手可能なタスクとして `tasks/BACKLOG.md` に起票する**。`/dev-loop` はここに起票されたものを実行するので、これがその前段になる。

**このスキルは実装しない。** コードは1行も変えず、BACKLOG（と必要なら「要決定」）だけを更新する。

## 手順

0. **現状の同期（必須）**: `git log --oneline -15` と `tasks/BACKLOG.md` を読む。**既に `done`／`todo`／`blocked` で存在する要望を二重に起票しない**（過去に、完了済みタスクの重複実装で別タスクの成果を消す事故があった）。同じ内容が既にあれば起票せず、そのタスクIDを案内して終わる。

1. **要望を1文に言い換える**: 「誰が・どの画面で・何ができるようになるか」の形にする。読み取れない情報があるときは推測で埋めず、**着手に必要な最小限だけ**を質問する（デザインの細部・将来の拡張は聞かない）。

2. **正本と照合する**（この順で確認する）:
   - **PRD §3.2「MVPでやらないこと」に該当しないか。** 該当するなら**起票せず**、スコープ外である旨と、それでも進めるならPRDの改定が必要であることを伝えて終わる。
   - どの機能ID（A/L/N/P/S/K/M/O）・画面（SC-01〜11）・AI実行（GEN/NEWS/LRN/MD-MERGE/SUGGEST）に紐づくか。紐づく正本が無い＝**新しい仕様**なら、PRDまたは要件詳細の改定がタスクの一部に含まれる。
   - 既存の実装で既に満たせていないか（満たせているなら使い方を案内して終わる）。

3. **大きさを決めて分割する**: **1タスク = 1コミットで完了できる大きさ**にする。画面追加・DB変更・AI実行の追加が同時に必要なら分ける。目安は S（半日以内）／M（1日）／L（それ以上＝分割を検討）。L のまま起票するのは、分割すると途中状態で動かなくなる場合だけにする。

4. **既存の書式どおりに起票する**（`tasks/BACKLOG.md` 冒頭の運用ルールに従う）:

   ```
   ### <ID>: <タスク名> `todo`
   - 参照: <docsの該当ID・節> / 依存: <タスクID または なし> / サイズ: <S|M|L>
   - 完了条件:
     - <動作で確認できる形で書く>
     - <異常系・空状態も1行入れる>
   - メモ: <なぜ必要か・実装時に注意する点・既知の制約>
   ```

   - **ID**: 該当マイルストーン節の連番の次を使う（例 `T-M7-30` の次は `T-M7-31`）。性質が既存マイルストーンに合わないときは新しい節の追加を提案し、**節の新設はユーザーに確認してから**行う。
   - **配置**: 該当マイルストーン節の末尾に足す。優先度が高いなら節内の順序を上げてよい（BACKLOGは上にあるものほど優先）。
   - **完了条件**: 「〜を改善する」ではなく「〜が表示される」「〜が保存される」のように**検証できる形**で書く。`/dev-loop` はこれをテストの根拠にする。
   - **参照**: 必ず docs の具体的な節を書く。書けないなら仕様が無いということなので、正本の追記もタスクに含める。

5. **判断が必要なものは「要決定」へ**: 費用・外部サービスの契約・法務・スコープの広がり・利用者に見える仕様の選択は勝手に決めない。`## 要決定・外部準備(ユーザー作業)` に `**D-<番号>: <論点>**` として追記し、**可能なら案A/案Bと推奨**を添える。タスク側の `依存` にその要決定を書く。

6. **不具合の場合**: 「再現手順」「実際に起きたこと」「期待する動作」を完了条件へ落とす。原因が既に分かっているなら メモ に書く。**原因不明のまま「調査する」だけのタスクにしない**（調査は `/dev-loop` の中で行われる）。

7. **コミット**: BACKLOG（と要決定）だけを `git add` してコミットする。メッセージは `chore(backlog): <要望の要約>を起票`。コードを変更していないことを `git status` で確認する。

8. **報告**: 起票したタスクID・サイズ・完了条件の要点、新たな要決定、そして**次に実行するコマンド**（`/dev-loop <ID>`）を伝える。

## ルール

- **実装しない。** 「ついでに直す」もしない。コードを変えたくなったら、それは `/dev-loop` の仕事。
- **推測で仕様を作らない。** 判断が要るものは要決定へ回し、暫定案を添える。
- 1回の実行で起票するのは**関連する1つの要望**まで。複数の要望をまとめて言われたら、分けて起票してよいが、それぞれ独立して着手できる形にする。
- PRD §3.2 に反する要望は起票しない（警告して終わる）。
- 既存タスクと重複する要望は起票しない（既存IDを案内する）。
- タスク名・完了条件・メモは日本語で書く。
