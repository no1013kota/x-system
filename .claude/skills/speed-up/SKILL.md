# speed-up：密結合をほどいて速くする

**遅さの正体はたいてい密結合。** 「画面がDBの都合を知っている」「判定が複数の層に散っている」「前の結果が要らないのに直列で待っている」——これらは同じ原因の別の症状で、ほどくと構造も速度も同時に良くなる。このスキルはその1本の作業に絞る。

`/refactor` との違い: あちらは内部品質全般（重複・命名・型・デッドコード）。**ここは「結合」と「待ち時間」だけ**を見て、必ず**数字**（往復回数・段数・実測ms）で前後を示す。

## 大原則（必ず守る）

1. **利用者に害があるならやらない。** 速さのために正しさ・分かりやすさを削らない。判定は下の「§ やる前の関門」で機械的に行う。**迷ったら実装せず、`tasks/BACKLOG.md` の「要決定」へ暫定案つきで起票して先へ進む**（CLAUDE.md 原則5）。
2. **推測で直さない。** 着手前に数字を取る。取れないものは「効きそう」でも触らない（効果が確認できない変更は、リスクだけが残る）。
3. **振る舞い保存。** 外部挙動・DB/API契約・画面仕様・エラー契約を変えない。変わるならこのスキルの対象外（`/dev-loop` へ）。
4. **1単位＝1コミット（WIP=1）。** 速度改善は「まとめて入れて、どれが効いたか分からない」が最悪。1つ入れて測る、を繰り返す。
5. **判定を消して速くしない。** 認可・契約・前提の検査は、**別の層へ移すのは可・消すのは不可**。移したときは移した先のテストを先に用意する。

## やる前の関門（利用者への影響判定）

候補ごとに次の表を上から当てる。**1つでも「やらない」に当たったら実装しない**（報告に理由を残す）。

| 変更 | 判定 | 理由 |
|---|---|---|
| **契約状態・利用枠・残量・課金情報をリクエストを跨いでキャッシュする** | **やらない** | 解約したのに使える／契約したのに使えない、が起きる。金銭と権利に関わる値は毎回読む |
| **認可・契約・前提の検査を削る**（「往復が減るから」） | **やらない** | 費用の出る操作が開く。移設は可（§大原則5） |
| **並列化・遅延化で失敗が握り潰される**（片方failで黙って空） | **やらない** | 「正常な空」と「失敗による空」が同じ見え方になる（原則1）。`Promise.allSettled` で理由を残す形にしてから並列化する |
| **費用の出る経路（AI・X API）をprefetch／先読みする** | **やらない** | 押していないのに課金される |
| **エラー・失敗の記録（Sentry・台帳）を削る** | **やらない** | 原因が辿れなくなる（原則2） |
| 表示件数を絞る・一部を後から読む | **画面に明示できるならやる**。できないなら**要決定へ** | 「全部見えている」と誤解させない（例: 「ほかN件は『すべて見る』から」） |
| 情報の出る順・位置・タイミングが変わる | **要決定へ**（暫定案つき） | 速さと引き換えに運営者の見え方が変わる。決めるのは運営者 |
| 内部だけの変更（直列→並列・重複往復の削除・純粋関数の抽出・境界の整理） | **やる** | 利用者から見た結果が同じ |

## 手順

1. **緑を確認**: `npm run typecheck && npm run lint && REQUIRE_DB=1 npx vitest run`。緑でなければ報告して着手しない。
2. **計測（飛ばさない）**: 「§ 何をどう測るか」で**現在値**を取る。数字が取れない候補は捨てる。
3. **候補出しと関門通し**: 「§ 見るべき結合」で洗い、*file:line / 症状 / 現在値 / 期待効果 / 関門* を付ける。`--audit` はここで止めて報告。
4. **1単位を実行**: 関門を通ったうち**効果が大きく影響範囲が狭いもの**を1件。テストが薄ければ先に特性テストを別コミットで足す。
5. **再計測**: 改善していなければ**戻す**（速くならなかった変更は複雑さだけを足す）。
6. **検証**: `CLAUDE.md`「変更影響 → 必須の検証」に従う。特に middleware/CSPは `build` ＋ `check:csp-nonce`、Server/Client境界は**実ブラウザ**（typecheckで出ない失敗がある・§落とし穴）。
7. **docs同期＋コミット**: `/doc-sync`（往復・段数は要件01 §5/§6・要件06）。**数字を本文へ残す**（「4段→2段」）。`perf(...)` / `refactor(...)` で1単位＝1コミット。報告に**前後の数字**・落とした候補と理由・要決定へ回した項目を書く。

## 何をどう測るか

| 対象 | 測り方 | 目安 |
|---|---|---|
| **サーバー側の直列往復（waterfall）** | 対象ページの `await` を上から読み、**前の結果を使っていない `await` が連続していないか**数える。「N段」と記録する | 依存が無いのに2段以上あれば候補 |
| **全リクエストに乗る処理** | `src/proxy.ts` → `src/lib/supabase/update-session.ts` の `updateSupabaseSession` を読む。ここは**全遷移**を通るので、1本の往復が全画面に効く | DB・外部HTTPが1つでもあれば最優先候補 |
| **同一リクエスト内の重複読み取り** | 同じ関数が複数のServer Componentから呼ばれていないか。`React cache()` でラップ済みかを確認 | 未ラップの共通読み取りは候補 |
| **実測の遷移時間** | **本番ビルドで測る**（`npm run build` ＋ `PORT=<別> npx next start`、`E2E_BASE_URL` を向ける）。一時specで `page.goto` → 主要要素が見えるまでを3回測って中央値。計測用specはコミットしない | 前後比較にだけ使う。**`next dev` の数字は±150msぶれる**ので、往復1本ぶんの改善は埋もれて見えない（2026-08-29に実際に埋もれた） |
| **PostgREST経由の読み取り**（`admin.from(...)`） | pooled接続（`getPool()`）と違いHTTPを1往復する。**同じ行を2か所から読んでいないか**を先に見る | 同じ`profiles`行を画面とApp Shellで別々に読む形は候補（T-M8-355/361で2画面ぶん削除） |
| **取得件数** | 一覧・履歴の `limit` の有無。無ければデータが増えるほど遅くなる | limit 無しは候補（ただし件数の明示とセット） |
| **クライアントへ送る量** | `npm run build` の route ごとのサイズ。`"use client"` が必要以上に上位に付いていないか | 目に見えて大きい route だけ扱う |

計測用の一時spec（`e2e/tmp-*.spec.ts` に置き、**必ず消す**）:

```ts
const t0 = Date.now();
await page.goto("/app/posts");
await expect(page.getByRole("heading", { name: "投稿作成" })).toBeVisible();
console.log("elapsed", Date.now() - t0);
```

## 見るべき結合（候補チェックリスト）

- **判定が散っている**: 同じ条件（契約・権限・上限）が複数の層に書かれている。→ **1か所を正本にして他は導出**。派生が消えると往復も消えることが多い（例: 画面の可否判定を1か所へ寄せた結果、proxyのDB読み取りが不要になった・T-M8-268）
- **直列 await**: 依存の無い取得が縦に並んでいる。→ `Promise.all` で1波に（T-M8-67で layout 5段→2段・ホーム約9段→2段）
- **重複読み取り**: 同じ profile / アカウントを画面内で何度も読む。→ `React cache()`（リクエスト内メモ化）
- **書き込みが読み取り経路に混ざっている**: 表示のたびに upsert する等。→ read-first にして、欠損時だけ修復
- **UIがDBの都合を知っている**: 画面が生SQL相当の形を受け取る。→ 表示に必要な形へ変換する層を挟む
- **副作用が中核に埋まっている**: DB・provider・時刻が関数内で直接呼ばれ、テストで差し替えられない。→ 注入（このリポジトリの既定の作法）
- **境界の乱れ**: `server-only` のものがクライアント側から辿れる／client componentが不必要に上位にある
- **上限が無い取得**: 件数が増えるほど遅くなる経路

## 落とし穴（実際に踏んだもの）

- **`TabNav`（`src/components/app-shell/tab-nav.tsx`）本体をclient化してはいけない。** `hrefFor`（関数props）がServer/Client境界を越えられず、**全タブページが実行時エラー**になる。**typecheckでは検出できない**（T-M8-67で実際に踏み、E2E10件全滅→切り戻した）。境界を動かす変更は必ず実ブラウザで確認する。
- **静的化・ISRで速くする道は塞がれている。** nonceベースCSPのため全ルートが `force-dynamic`（ADR-0005・要件01 §8）。prerenderへ寄せる提案はしない。**prerenderされたページはscriptが1本も実行されず、HTTPは200のまま画面だけ壊れる**（2026-08-14に18日間気付けなかった）。触れたら `npm run check:csp-nonce`。
- **`React cache()` はリクエスト内だけ。** リクエストを跨ぐキャッシュ（`unstable_cache`・`revalidate`）を契約・利用枠・下書きに使わない（§関門）。
- **middlewareに処理を足さない。** 全リクエストを通るので、ここの1往復は全画面の遅延になる。逆に削ると効果が最も大きい。
- **「速くなった気がする」で終わらせない。** 前後の数字が無い変更はコミットしない。

## Definition of Done

- [ ] 前後の**数字**がある（往復回数・段数・実測ms のいずれか）
- [ ] 関門を全候補に当てた（落とした候補と理由を報告に書いた／判断が要るものは「要決定」へ起票した）
- [ ] 外部挙動を変えていない（テスト緑・契約不変）。境界を動かしたら実ブラウザで確認した
- [ ] `CLAUDE.md`「変更影響 → 必須の検証」の該当行を実行した
- [ ] `/doc-sync` 実行済み（数字を正本へ残した、または影響なしを理由付きで確認）
- [ ] 1単位でコミットした（`perf(...)` / `refactor(...)`・Co-Authored-By 付き）
