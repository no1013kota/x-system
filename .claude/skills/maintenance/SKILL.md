# maintenance：定期点検

**変更していないのに壊れる部分**を点検する。CIとテストは「変更したときに」壊れたことを教えるが、外部APIの仕様変更・新しい脆弱性・データの滞留・費用の増加は**時間の経過だけで**起こる。2026-07-28、Anthropicの Web Search tool が `allowed_callers` を要求するようになり、コード変更なしで生成が全滅した。

運営者は1人なので、**判断はまとめて求め、実行できることは実行してから報告する**。

## 週次（引数なし・所要 3〜5分＋実費 約50円）

上から順に実行し、**途中で失敗しても止めずに最後まで進める**（結果をまとめて報告するため）。

1. **状態確認**: `npm run doctor`。⚠️/❌ があれば原因を調べる。
2. **外部APIの受理確認**: `npm run check:providers`（実費ほぼ0円）。落ちたら**その日の変更ではなく provider 側の仕様変更**を疑い、公式ドキュメントで該当箇所を確認する。
3. **実物1周**: `npm run smoke:live -- --account <xAccountId>`（実費 約45円・要 `npm run dev`）。生成・画像・ニュースの成果物と、報告に出る生成物の形（字数・改行・タグ・URL）を目で見る。
4. **依存の脆弱性**: `npm run audit:check`。新しい high/critical が出ていたら、allowlist に足す前に**上げられるか**を試す（`overrides` でnested版も寄せられることがある。T-M7-32）。
5. **溜まったデータ**: `npm run db:clean-test-data`（まず dry-run で件数を見る）。送信待ちのお知らせメールとテストユーザーが溜まっていたら `-- --apply`。
6. **未pushの確認**: `git branch -vv` で未pushコミット数を見る。溜めすぎない。

**報告に含める**: doctorの⚠️/❌、check:providers と smoke:live の結果と実費、audit の増減、掃除した件数、未pushコミット数、**運営者に決めてほしいこと**。

## 月次（`/maintenance monthly`・週次に追加して実行）

7. **費用の実績**: 当月と前月の `external_api_usage_events` を provider 別に集計し、想定と比べる。増えていれば原因（生成回数・Web検索回数・画像枚数）を分解して示す。
8. **バックアップの復元テスト**: [DBバックアップと復元](../../../docs/operations/database-backup-restore.md) の手順で**復元まで**試す。取れているだけでは復元できるとは言えない。
9. **外部APIの変更確認**: X API・Anthropic・OpenAI・Stripe の変更履歴を確認し、`docs/` の「実装時に要確認」注記のある箇所と突き合わせる。破壊的変更があれば `/add-task` で起票する。
10. **古いデータの確認**: `news_fetch_outcomes`・`cron_runs`・`notifications` の保持（40日）が効いているかを件数で見る。増え続けていたら cleanup が動いていない。

## ルール

- **実費が出る手順（3・7）は、実行前に金額を伝えてから実行する。** 週次の想定は約50円。
- 外部へ副作用を出す操作（X実投稿・実課金・第三者へのメール）はしない。点検は読み取りと非productionに限る。
- 直せるものはその場で直す。仕様判断が要るものは `tasks/BACKLOG.md` の「要決定」へ追記して先へ進む。
- 見つけた不具合は `/add-task` で起票する（この場で実装しない。点検と修理を混ぜると、点検が終わらない）。
- 定期実行するなら `/loop /maintenance`（セッション中）またはクラウドスケジュール（`/schedule`）で週1回にする。

## なぜこれが必要か

[開発とテストの進め方](../../../docs/operations/development-and-testing.md) §9 の7層はすべて**変更起点**で走る。変更していないのに壊れる次の4つは、どの層も捕まえない。

| 時間経過で壊れるもの | 週次で見る手順 |
|---|---|
| 外部APIの仕様変更（`allowed_callers` の件） | 2・3 |
| 新しい脆弱性の公表 | 4 |
| データの滞留（送信待ちメール53件・テストユーザー693件） | 5 |
| 費用の増加 | 1（doctor に当月費用が出る）・7 |
