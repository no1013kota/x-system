# doc-sync：ドキュメント同期

コードとドキュメントの乖離を検出し、**その場で解消する**。

## 手順

1. **範囲を決める** — 引数があれば `git diff <引数>`、なければ未コミットの変更（`git diff HEAD` ＋ 未追跡ファイル）。
2. **影響先を判定する** — `docs/README.md` §1の地図と §2の所有ルールで決める。
3. **突き合わせて更新する** — 下の§書き方。
4. **機械検査を回す** — `npm run check:doc-dates` と `npm run check:doc-refs`。**新規ファイルはstageしないと「実在しない」と報告される**（`git ls-files` で判定するため）。
5. **報告する** — 表形式。「影響なし」も理由付きで書く。黙って省略しない。

   | 変更内容 | 影響ドキュメント | 対応 |
   |---|---|---|
   | 投稿生成APIを追加 | 要件05 | 更新済み |
   | リファクタのみ | — | 影響なし（外部仕様の変更なし） |

## 書き方

- **仕様レベルで書く。** コードの逐語的な説明にしない。
- 数値・一覧は**同じものを2か所に置かない**（片方だけ古くなる）。所有先は `docs/README.md` §2。
- 更新した文書は冒頭の**更新日**を直す。仕様が変わったなら末尾の**変更履歴**にも追記する。
- 要件そのものが変わるときだけPRDを更新する。
- **新しい一覧や数値を書くなら、突き合わせる検査も同時に作る**（既存の仕組みは `docs/README.md` §3）。作れないなら「実測が正」と明記して日付を添える。
- docsに無い設計判断が実装に入っていたら `docs/decisions/` へADRを追加する。

## --full（監査モード）

差分ではなく実装全体と `docs/` を突き合わせ、3種の乖離を列挙して直す。

| 種別 | 内容 |
|---|---|
| (a) | docsに記載があるが未実装（未実装が正しいなら「未実装」と明記されているか） |
| (b) | 実装されているがdocsに記載がない |
| (c) | 記述が実装と食い違って古い |

対象が広いので、機能領域ごとにサブエージェントへ並列で分担させてよい。

## 注意

- **このスキル内で完結させる。**「あとで更新する」で終わらせない。
- PRDのスコープ（§3.2 MVPでやらないこと）に反する実装を検出したら、更新せずユーザーに警告する。
