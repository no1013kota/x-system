# doc-sync：ドキュメント同期チェック

コードとドキュメントの乖離を検出し、その場で解消する。

## 手順

1. **変更範囲の特定**: 引数があればその範囲（`git diff <引数>`）、なければ未コミットの変更（`git diff HEAD` + 未追跡ファイル）を対象にする。
2. **影響ドキュメントの判定**: `document/README.md` のドキュメントマップを読み、各変更が影響するドキュメントを判定する。
3. **突き合わせと更新**: 各ドキュメントの該当箇所と実装を突き合わせ、乖離があれば更新する。
   - 仕様レベルの記述にする。コードの逐語的な説明は書かない
   - 要件変更を伴う場合のみPRDを更新し、末尾の変更履歴に追記する
   - ドキュメントにない新しい設計判断が実装に含まれていたら `document/decisions/` にADRを追加する
   - 更新したドキュメントの冒頭の最終更新日を更新する
4. **結果報告**: 以下の表形式で報告する。「影響なし」と判断した場合も理由を明示する。黙って省略しない。

   | 変更内容 | 影響ドキュメント | 対応 |
   |---|---|---|
   | （例）投稿生成APIを追加 | api-spec.md | 更新済み |
   | （例）リファクタのみ | — | 影響なし（外部仕様の変更なし） |

## --full（監査モード）

差分ではなく実装全体と `document/` を突き合わせ、次の3種の乖離を列挙して修正する:

- (a) ドキュメントに記載があるが未実装のもの（未実装が正しい場合は「未実装」と明記されているか確認）
- (b) 実装されているがドキュメントに記載がないもの
- (c) 記述が実装と食い違って古くなっているもの

対象が広いため、機能領域ごとにサブエージェントへ並列で分担させてよい。

## 注意

- ドキュメントの更新はこのスキル内で完結させる。「あとで更新する」という報告で終わらせない。
- PRDのスコープ（§3.2 MVPでやらないこと）に反する実装を検出したら、更新せずユーザーに警告する。
