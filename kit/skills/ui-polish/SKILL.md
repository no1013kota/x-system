# ui-polish：画面の実装と仕上げ

既存デザインシステムを守って実装し、**実ブラウザで完成状態まで**確認する。実装だけで完了にしない。

## 手順

1. **正本と既存を読む**
   - 仕様: `docs/PRD.md`／`docs/requirements/` の該当画面の要件／関連するAPIの要件
   - 既存: 対象の画面（route）・親layout・共通UI部品のディレクトリ・グローバルCSS（デザイントークンの定義）・UIライブラリの設定ファイル（shadcn/ui を使っていれば `components.json`）
   - **既存コンポーネントとデザイントークンを最優先。任意値を増やさない。** 新規部品が要るときは、shadcn/ui を使っていれば shadcn MCP でレジストリを検索してから作る。
2. **方針を一言で決める** — 目的・主利用者・最優先アクション・情報階層。新規画面は美的方向を1つ選び、既存更新は現行システムとの一貫性を優先。
3. **実装する** — 使っているフレームワーク・スタイリング・UIライブラリの既存構成（ルーティング・サーバー／クライアント境界を含む）に従う。
4. **実ブラウザで検証する**（下の§検証）
5. **報告** — 方針／再利用・追加した部品とトークン／確認した幅・テーマ・状態／修正点／未解消事項。**未解消があれば完了扱いにしない。**

## 実装の決まり

| 対象 | 決まり |
|---|---|
| 色・余白・角丸・影 | CSS変数か既存ユーティリティを使う（直値を書かない） |
| 状態 | hover / focus-visible / disabled / loading / empty / error / success を該当分すべて |
| アクセシビリティ | 主要導線はWCAG 2.2 AA（キーボード・明瞭なfocus・label・色以外の状態表現） |
| モーション | `prefers-reduced-motion` を尊重 |
| 仕様変更 | 画面挙動を変えたら**同じ作業単位で**正本docsを更新 |

## 操作結果の通知は共通のトースト（通知）の仕組みで出す

画面内へ独自の成功／失敗メッセージを足さない。通知の決まりが `docs/requirements/` にあればそれに従う。**共通の仕組みがまだ無いなら、画面ごとの独自メッセージで代用せず、先に共通の仕組みを1つ用意して通知の決まりを `docs/requirements/` へ書いてから載せる**（仕組みの選定に運営者の判断が要るなら `tasks/BACKLOG.md` の「要決定」へ暫定案を添えて回す）。判断は3つだけ。

- **成功も必ず出す。** 無言で終わると、成功したのか何も起きなかったのか区別できない（CLAUDE.md 前提の原則1「黙って壊れない」）。
- **トーストに載せないのは3種類**: 入力検証／ボタンを伴う案内／恒常表示・画面状態。理由と例は `docs/requirements/` の通知の決まり（あれば参照する）。
- **インライン通知を消すのとトーストを足すのは同じコミットで行う。** 片方だけだと「2か所に出る」か「どこにも出ない」になる。トーストの仕組みによっては、初期化（Provider 等）の外で呼んでも例外を投げずに何もしない（no-op）ため、**呼んでいるのに何も出ない事故が静かに起きる**。移行した画面ごとに E2E のテストファイルへ「実際に出る」テストを1件足し、呼び出しを消すと落ちることを確認する。

## 検証（実ブラウザ）

| 項目 | やること |
|---|---|
| 起動 | 開発サーバーを起動する（起動コマンドは `package.json` の `scripts` を正とする）。OAuth など外部サービスが `localhost` を許可しない場合は **`http://127.0.0.1:<ポート>`** で開く（HMR〔ホットリロード〕の許可オリジンも、フレームワークの開発サーバー設定で同じホストに合わせる） |
| ランタイム | Next.js DevTools MCP を使っていれば、ランタイム／ビルド／Hydrationエラーを確認する（無ければブラウザのコンソールと開発サーバーのログで同じものを見る） |
| 認証必須画面 | テストユーザーでログインして開く（storage-stateは playwright-cli 参照） |
| 画面幅 | Playwright CLIで Desktop 1440 / Tablet 768 / Mobile 390 のスクショ |
| 実データ | **本物のデータを載せて描画を確認**（画像・表・グラフなど、外部から取得したり生成したりして表示するもの）。要素の存在ではなく実際に読み込めたこと（画像なら `naturalWidth>0`）。CSP違反・署名URL・デコード失敗は実物でしか出ない（過去に、別オリジンから読み込む画像がCSPに弾かれ、ローカルでは必ず非表示になっていたことがある） |
| 潰すもの | 横スクロール・重なり・文字切れ・focus/label欠落・色依存の状態・コンソールエラー・レイアウトシフト |

修正したら同条件で再確認する。**スクショ／traceはコミットしない。**
